## Detailed Findings

### CRIT-001: Missing ErrorBoundary Component

**Pattern:** 5.51 (ErrorBoundary Integration)
**Severity:** CRITICAL
**File:** `client/src/main.tsx`, `client/src/App.tsx`

**What's Wrong:**
No ErrorBoundary component exists in the codebase. No file at `client/src/components/ErrorBoundary.tsx`. If any React component throws during render, the entire app will white-screen with no recovery.

**The Fix:**
Create `client/src/components/ErrorBoundary.tsx` and wrap Routes in `main.tsx`:
```tsx
import { Component, ErrorInfo, ReactNode } from 'react';

interface Props { children: ReactNode; }
interface State { hasError: boolean; }

export class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false };
  static getDerivedStateFromError(): State { return { hasError: true }; }
  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    console.error('ErrorBoundary caught:', error, errorInfo);
  }
  render() {
    if (this.state.hasError) {
      return (
        <div className="flex items-center justify-center h-screen">
          <div className="text-center">
            <h1 className="text-2xl font-bold mb-2">Something went wrong</h1>
            <button onClick={() => this.setState({ hasError: false })} className="text-blue-600 underline">
              Try again
            </button>
          </div>
        </div>
      );
    }
    return this.props.children;
  }
}
```

### CRIT-002: Registration Creates Org + User Without Transaction

**Pattern:** 5.55 / 5.61 (Database Transaction Detection)
**Severity:** CRITICAL
**File:** `server/services/auth.service.ts:36-47`

**What's Wrong:**
The `register()` function creates an organization (line 36) and then creates a user (line 41) as two separate database operations without a transaction wrapper. If user creation fails (e.g., duplicate email race condition), an orphaned organization is left in the database.

**Code:**
```typescript
// Lines 36-47: Two separate INSERT operations, no transaction
const [org] = await db.insert(organizations).values({...}).returning();
const [user] = await db.insert(users).values({...}).returning();
```

**The Fix:**
```typescript
const result = await db.transaction(async (tx) => {
  const [org] = await tx.insert(organizations).values({
    name: organizationName,
    slug: slug + '-' + Date.now(),
  }).returning();

  const [user] = await tx.insert(users).values({
    organizationId: org.id,
    email, passwordHash, name, role: 'admin',
  }).returning();

  return { org, user };
});
```

### CRIT-003: Response Envelope Format Mismatch (33 occurrences)

**Pattern:** 5.8 (Response Envelope Verification)
**Severity:** CRITICAL
**File:** All route files (`server/routes/*.routes.ts`)

**What's Wrong:**
All 33 route handlers use `res.json({ success: true, data: result })` format. The API contract (Section 2) specifies `{ data: <T>, meta: { timestamp: "..." } }` format. The `success` field is not in the spec, and the required `meta.timestamp` field is entirely missing.

**Impact:** Every single API response violates the contract. Frontend may work with current format, but the spec compliance is 0%.

**The Fix:**
Create response helpers in `server/utils/response.ts`:
```typescript
export function sendSuccess(res: Response, data: any, status = 200) {
  return res.status(status).json({
    data,
    meta: { timestamp: new Date().toISOString() }
  });
}

export function sendCreated(res: Response, data: any) {
  return sendSuccess(res, data, 201);
}

export function sendPaginated(res: Response, data: any[], pagination: PaginationMeta) {
  return res.json({
    data,
    meta: { timestamp: new Date().toISOString() },
    pagination
  });
}
```
Then replace all `res.json({ success: true, data: ... })` calls across all route files.

### CRIT-004: Direct parseInt on Route Parameters (48 occurrences)

**Pattern:** 5.6 / 5.32 (parseIntParam / Utility Function Consistency)
**Severity:** CRITICAL
**File:** All route files except `auth.routes.ts`

**What's Wrong:**
All route files use `parseInt(req.params.projectId, 10)` directly (48 total occurrences). The API contract (Section 3) requires `requireIntParam()` utility for consistent validation. Direct parseInt silently returns NaN for non-numeric input without proper error messaging.

**Example (projects.routes.ts:41):**
```typescript
const projectId = parseInt(req.params.projectId, 10); // No NaN check!
```

**The Fix:**
Create `server/utils/validation.ts` with `requireIntParam()` and replace all `parseInt(req.params...)` calls:
```typescript
export function requireIntParam(value: string | undefined, paramName: string): number {
  if (!value) throw createAppError('VAL-001', `Missing required parameter: ${paramName}`);
  const parsed = parseInt(value, 10);
  if (isNaN(parsed) || parsed <= 0) throw createAppError('VAL-001', `Invalid ${paramName}: must be positive integer`);
  return parsed;
}
```

### HIGH-001: Math.random() in Server Code

**Pattern:** 5.21 / 5.47 (Insecure Random Detection)
**Severity:** HIGH
**File:** `server/middleware/upload.ts:18`

**What's Wrong:**
```typescript
const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1e9);

`Math.random()` is not cryptographically secure. While this is for filename generation (not security tokens), using it in server code is a bad practice and violates Pattern 5.47.

**The Fix:**

import crypto from 'crypto';
const uniqueSuffix = Date.now() + '-' + crypto.randomBytes(6).toString('hex');
```

### HIGH-002: Project Soft Delete Cascade Without Transaction

**Pattern:** 5.55 / 5.69 (Transaction / Soft Delete Cascade)
**Severity:** HIGH
**File:** `server/services/projects.service.ts:106-124`

**What's Wrong:**
`deleteProject()` soft-deletes the project and then cascades to sources, processingRuns, and datasets in 4 separate operations without a transaction. If any cascade step fails, children become orphaned (active but parent deleted).

**The Fix:**
```typescript
export async function deleteProject(projectId: number, organizationId: number) {
  await db.transaction(async (tx) => {
    const now = new Date();
    const [project] = await tx.update(projects).set({ deletedAt: now, updatedAt: now })
      .where(and(eq(projects.id, projectId), eq(projects.organizationId, organizationId), isNull(projects.deletedAt)))
      .returning();
    if (!project) throw createAppError('DB-003', 'Project not found');
    await tx.update(sources).set({ deletedAt: now, updatedAt: now }).where(eq(sources.projectId, projectId));
    await tx.update(processingRuns).set({ deletedAt: now, updatedAt: now }).where(eq(processingRuns.projectId, projectId));
    await tx.update(datasets).set({ deletedAt: now, updatedAt: now }).where(eq(datasets.projectId, projectId));
  });
}
```
